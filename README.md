# Good Food — система заказов

Админ-панель и мини-приложение Telegram. Всё работает на своём компьютере в Docker: сервер, база Postgres, картинки, резервные копии и расписание.

## Быстрый старт

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/). В его настройках включите запуск при входе в систему, тогда сервер будет подниматься сам после перезагрузки.
2. Скопируйте `.env.example` в `.env` и заполните (см. ниже).
3. В папке проекта выполните:

```bash
docker compose up -d
```

4. Откройте http://localhost:3000/admin. **Логин** — `ADMIN_CHAT_ID`, **пароль** — `ADMIN_PASSWORD` из `.env` (см. «Первый вход»).

Первый запуск собирает образ, это занимает пару минут. Порт 3000 открыт только на этом компьютере.

## Настройки `.env`

| переменная | обязательно | что это |
|---|---|---|
| `JWT_SECRET` | да | случайная строка, например `openssl rand -hex 32`. Если сменить, всех разлогинит |
| `ADMIN_CHAT_ID`, `ADMIN_PASSWORD` | для первого входа | первый админ, см. «Первый вход» |
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | да | любая случайная строка |
| `TELEGRAM_ADMIN_GROUP_ID` | да | Chat ID группы операторов (отрицательный). Узнать: добавить бота в группу и отправить `/id` |
| `TELEGRAM_KITCHEN_GROUP_ID` | для «Кухни» | Chat ID группы кухни |
| `FRONTPAD_APIKEY` | для FrontPad | ключ API FrontPad. Пусто — интеграция выключена |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | при переносе | откуда загрузить данные при первом запуске, см. ниже |
| `POSTGRES_PASSWORD` | нет | пароль базы, по умолчанию `goodfood`. Задавать только до первого запуска |
| `APP_PORT` | нет | порт на компьютере, по умолчанию `3000` |
| `CLOUDFLARE_TUNNEL_TOKEN` | для туннеля | см. «Доступ из интернета» |

Если вы поменяли `.env` при работающем сервере, выполните `docker compose up -d` ещё раз: контейнер пересоздастся с новыми настройками.

## Первый вход

Админов создают в самой админке, поэтому первого задают в `.env`:

- `ADMIN_CHAT_ID` — ваш личный Chat ID в Telegram (написать боту `/id` или @userinfobot);
- `ADMIN_PASSWORD` — пароль компании-оператора: латиница, цифры и дефис, до 32 символов.

При каждом запуске сервер проверяет, есть ли пользователь с этим Chat ID. Если нет, создаёт его админом компании с этим паролем (саму компанию «Good Food» тоже создаёт, если такой нет). Существующего пользователя сервер не меняет. Если вы потеряли доступ, удалите пользователя и перезапустите сервер: админ создастся снова.

Если заданы ключи Supabase, сначала загружаются данные, а админ создаётся после, только если его Chat ID нет среди загруженных. Кнопка «Загрузить данные из Supabase» заменяет все данные, в том числе этого админа; он вернётся при следующем запуске.

## Загрузка данных из Supabase при первом запуске

База после первого запуска пустая. Чтобы перенести в неё старые данные:

1. **До первого запуска** впишите в `.env` ключи из Supabase → Project Settings → API:
   - `SUPABASE_URL` — Project URL (`https://xxxx.supabase.co`);
   - `SUPABASE_SERVICE_ROLE_KEY` — ключ `service_role` (не `anon`).
2. `docker compose up -d`. Сервер видит пустую базу и сам загружает все таблицы и картинки. Ход загрузки можно смотреть так:

```bash
docker compose logs -f app
```

   В конце появится `[import] done`. После этого можно войти со старыми Chat ID и паролем компании.
3. Если загрузка не удалась (неверный ключ, нет интернета), база остаётся пустой: исправьте `.env` и снова выполните `docker compose up -d`.

В Supabase ничего не меняется. Если сервер уже запускали без ключей, база тоже пустая: достаточно добавить ключи и выполнить `docker compose up -d`.

**Последняя загрузка перед переходом.** Пока старая система работает, в ней появляются новые данные. В день перехода нажмите **Настройки → Данные из Supabase → «Загрузить данные из Supabase»**. Все данные на сервере заменяются, текущие перед этим сохраняются в резервную копию. Настройка «Адрес сервера» сохраняется. Кнопка срабатывает один раз, потом карточка исчезает.

Загрузить заново из командной строки (заменит всё):

```bash
docker compose run --rm app node scripts/import-supabase.js --replace
```

После перехода ключи Supabase из `.env` можно удалить.

## Адрес сервера (URL)

Telegram работает только с публичным **https**-адресом. Без него бот не получает сообщения, мини-приложение не открывается, а у уведомлений в группе операторов нет кнопок «Открыть в админ-панели».

Адрес задаётся не в `.env`, а в админке: **Настройки → Адрес сервера**. Введите `https://ваш-домен` без `/` в конце и нажмите «Сохранить». Сервер сразу направляет вебхук бота на этот адрес и показывает, принял ли его Telegram. Если адрес поменялся, просто сохраните новый.

Затем в @BotFather → ваш бот → Bot Settings → Menu Button (или Mini App) укажите `https://ваш-домен/app/`.

## Доступ из интернета (Cloudflare Tunnel)

Так сервер получает https-адрес без проброса портов на роутере.

1. Cloudflare Zero Trust → Networks → Tunnels → Create tunnel (Cloudflared). Токен впишите в `.env` → `CLOUDFLARE_TUNNEL_TOKEN`.
2. В туннеле добавьте Public Hostname: ваш домен → Service `http://app:3000`.
3. Запустите вместе с туннелем:

```bash
docker compose --profile tunnel up -d
```

4. Задайте адрес в админке (см. «Адрес сервера»).

## Повседневные команды

| что сделать | команда |
|---|---|
| запустить | `docker compose up -d` |
| логи | `docker compose logs -f app` |
| остановить | `docker compose down` |
| обновить после замены файлов | `docker compose up -d --build` |
| забрать резервные копии в папку `./backups` | `docker compose cp app:/data/backups ./backups` |

Данные хранятся в томах Docker: `pgdata` (база), `uploads` (картинки), `backups` (копии). `docker compose down` их не удаляет. **`docker compose down -v` удаляет все данные.**

## Резервные копии

- Каждый день в 03:00 по Кишинёву. Если сервер в это время был выключен, копия делается, как только он заработает в тот же день.
- Хранятся 30 дней, самая свежая не удаляется никогда.
- **Настройки → Резервные копии:** «Создать копию» и «Восстановить». Перед восстановлением текущие данные тоже сохраняются.

## Без Docker (для разработки)

Нужен Node.js 20+. Postgres ставится вместе с `npm install`, данные лежат в `.local/`.

```bash
npm install
npm run local
```

Остановить: Ctrl+C (если Postgres остался работать — `npm run local:stop`). Загрузка из Supabase: `npm run local:import -- --replace`. Начать с нуля: удалить папку `.local`.

### Роли и вход

- **Админ** — сотрудник компании-оператора. Входит в `/admin` по Chat ID и паролю своей компании. Сессия 12 часов.
- **Владелец** и **сотрудник** — люди из компаний-клиентов. Работают только в мини-приложении Telegram, в обычном браузере оно не открывается.

Регистрация: человек нажимает `/start` в боте, в приложении вводит пароль компании, в группу операторов приходит заявка, админ открывает доступ. Пароль сам по себе никого не пускает.

Пароль компании: латиница, цифры и дефис, до 32 символов. **Пользователи → Компании → Изменить:** назначить владельца (он один), перевыпустить пароль (все сотрудники теряют доступ до ввода нового), выключить доступ всей компании. Разрешить владельцу самому перевыпускать пароль: **Настройки → Пароль компании**.

Смена Chat ID пользователя, который уже входил, требует подтверждения, и об этом сообщается в группу операторов.

### Заказы

- Вкладки «Заказ» и «Возврат». Цены считает сервер.
- Новый заказ приходит в группу операторов. Админ подтверждает или отклоняет его в **Заказы**, заказчик получает уведомление.
- Неподтверждённый заказ можно изменить, любой можно повторить.
- **Настройки → Изменение заказов:** время закрытия приёма, поздние заказы (на завтра или не принимать), отмена неподтверждённых.
- Возврат только из истории, не больше купленного. Позицию, снятую с продажи, заказать нельзя, но вернуть можно.

### FrontPad

Подтверждённый заказ отправляется в FrontPad с доставкой на следующий день. У каждой позиции должен быть **Артикул FrontPad**, иначе заказ не отправится. Если FrontPad отказал, заказ остаётся «Новым» и видна причина.

**Настройки → FrontPad:** `enabled` (выкл по умолчанию), `simulation` (**вкл**: всё пишется в журнал, но не отправляется), `verbose`, `send_returns` (возвраты по «Артикулу возврата»), `delivery_time` (10:00). Кнопка «В FrontPad» отправляет повторно.

### Сообщения и уведомления

- **Рассылка:** до 1000 символов и одно фото, всем, выбранным компаниям или людям с открытым доступом. Отправленное можно удалить из чатов.
- **Уведомления:** повторяются по дням недели и времени (по Кишинёву). Сервер проверяет расписание каждые 5 минут. Если опоздание больше часа, уведомление не отправляется. Неудачная отправка повторяется до трёх раз. Получатель «Кухне» — список на приготовление по подтверждённым заказам на сегодня.

### Бот

- `/start` — регистрация или подсказка, что делать дальше.
- `/id` — Chat ID текущего чата.
