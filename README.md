# Good Food — система заказов

Админ-панель и мини-приложение Telegram для приёма заказов.

**Стек:** Node.js 24, PostgreSQL 17, Docker Compose. Сервер, база, картинки, резервные копии и расписание работают в контейнерах.

## Требования

- Docker Engine с Docker Compose v2.
- Домен с HTTPS: reverse proxy (nginx, Caddy, Traefik) передаёт запросы на `http://127.0.0.1:3000` с заголовками `X-Forwarded-For` и `X-Forwarded-Proto`. По ним сервер определяет адрес клиента для ограничения попыток входа.

## Запуск

```bash
cd good_food            # корень репозитория, рядом с docker-compose.yml
cp .env.example .env    # заполнить, см. «Конфигурация»
docker compose up -d
docker compose ps       # оба контейнера должны быть healthy
```

При первом запуске собирается образ и создаётся схема базы. Контейнеры перезапускаются автоматически, в том числе после перезагрузки сервера.

Приложение слушает только `127.0.0.1:3000`, поэтому напрямую из интернета недоступно. Весь внешний трафик идёт через HTTPS-прокси:

| адрес | что это |
|---|---|
| `https://домен/admin` | админ-панель |
| `https://домен/app/` | мини-приложение Telegram |

## Конфигурация

Все настройки задаются в файле `.env` в **корне репозитория**, рядом с `docker-compose.yml`. Docker Compose читает его только оттуда. Файл не хранится в git. После изменения выполните `docker compose up -d`.

| переменная | обязательна | описание |
|---|---|---|
| `JWT_SECRET` | да | ключ подписи сессий: `openssl rand -hex 32`. При смене все пользователи разлогиниваются |
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | да | случайная строка для проверки запросов Telegram |
| `TELEGRAM_ADMIN_GROUP_ID` | да | Chat ID группы операторов (отрицательное число, узнать командой `/id` в группе) |
| `TELEGRAM_KITCHEN_GROUP_ID` | нет | Chat ID группы кухни |
| `FRONTPAD_APIKEY` | нет | ключ API FrontPad. Без него интеграция выключена |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | нет | источник данных для первого запуска, см. ниже |
| `ADMIN_CHAT_ID`, `ADMIN_PASSWORD` | нет | первый администратор, если данные не переносятся |
| `POSTGRES_PASSWORD` | нет | пароль базы (по умолчанию `goodfood`). Действует только при создании базы |
| `APP_PORT` | нет | локальный порт приложения (по умолчанию `3000`) |

Публичный адрес сервера задаётся не в `.env`, а в админ-панели (см. «Адрес сервера и Telegram»).

## Перенос данных из Supabase

При первом запуске сервер сам загружает все таблицы и картинки из Supabase, если база пустая и заданы ключи.

1. До первого запуска укажите в `.env` данные из Supabase → Project Settings → API:
   - `SUPABASE_URL` — Project URL (`https://xxxx.supabase.co`);
   - `SUPABASE_SERVICE_ROLE_KEY` — ключ `service_role`.
2. Запустите `docker compose up -d` и дождитесь в логе (`docker compose logs -f app`) строки `[import] done`.
3. Войдите в админ-панель с прежними Chat ID и паролем компании.

Особенности:

- Загрузка выполняется только в пустую базу. Повторные запуски данные не затрагивают.
- Данные в Supabase не изменяются.
- При ошибке база остаётся пустой. Исправьте ключи и снова выполните `docker compose up -d`.
- Сообщение `orders: not imported (no such column here): locked` ожидаемо: эта колонка не используется.

**Финальная синхронизация.** В день перехода нажмите в админ-панели **Настройки → Данные из Supabase → «Загрузить данные из Supabase»**. Все данные заменяются актуальными, текущие перед этим сохраняются в резервную копию. Кнопка одноразовая.

Принудительная повторная загрузка (заменяет все данные):

```bash
docker compose run --rm app node scripts/import-supabase.js --replace
```

После перехода ключи Supabase можно удалить из `.env`.

## Первый администратор

Если данные не переносятся, задайте в `.env`:

- `ADMIN_CHAT_ID` — личный Chat ID в Telegram;
- `ADMIN_PASSWORD` — пароль компании: латиница, цифры и дефис, до 32 символов.

При запуске сервер создаёт администратора и компанию «Good Food», если пользователя с таким Chat ID ещё нет. Существующие пользователи не изменяются.

Вход в `/admin`: логин — `ADMIN_CHAT_ID`, пароль — `ADMIN_PASSWORD`.

## Адрес сервера и Telegram

Боту и мини-приложению нужен публичный HTTPS-адрес.

1. Админ-панель → **Настройки → Адрес сервера** → введите `https://домен` → «Сохранить». Сервер сразу регистрирует вебхук бота и показывает ответ Telegram.
2. @BotFather → бот → Bot Settings → Menu Button: `https://домен/app/`.

При смене домена повторите оба шага.

## Эксплуатация

| задача | команда |
|---|---|
| запуск | `docker compose up -d` |
| статус | `docker compose ps` |
| логи | `docker compose logs -f app` |
| остановка | `docker compose down` |
| обновление | `git pull && docker compose up -d --build` |
| выгрузить резервные копии | `docker compose cp app:/data/backups ./backups` |

Данные хранятся в томах Docker: `pgdata` (база), `uploads` (картинки), `backups` (резервные копии).

> **Внимание:** `docker compose down -v` безвозвратно удаляет все тома с данными.

### Резервные копии

- Автоматически каждый день в 03:00 (Europe/Chisinau). Если сервер был недоступен, копия создаётся при следующем запуске в тот же день.
- Хранятся 30 дней, последняя копия не удаляется.
- Ручное создание и восстановление: **Настройки → Резервные копии**. Перед восстановлением текущее состояние тоже сохраняется.

## Диагностика

| симптом | причина и решение |
|---|---|
| контейнер `app` перезапускается, в логе `JWT_SECRET is not set` | нет файла `.env` рядом с `docker-compose.yml` или в нём не задан `JWT_SECRET` |
| `password authentication failed` | `POSTGRES_PASSWORD` изменён после создания базы. Верните прежнее значение |
| `[import] startup load failed` | неверные ключи Supabase или нет доступа к интернету |
| бот не отвечает | не задан `TELEGRAM_WEBHOOK_SECRET`, не сохранён адрес сервера или домен недоступен по HTTPS |
| вход в админ-панель не сохраняется | панель открыта не по HTTPS |
| «Слишком много попыток» при входе | 10 неверных паролей за 15 минут. Подождите 15 минут или перезапустите `app` |

## Структура проекта

```
server.js        точка входа: миграции, планировщик, импорт, API, статика
src/lib/         база, Telegram, FrontPad, заказы, уведомления, резервные копии, импорт
src/routes/      auth, admin, app (мини-приложение), telegram (вебхук), files
public/admin/    админ-панель
public/app/      мини-приложение
db/migrations/   миграции, применяются при запуске (новые изменения — новым файлом)
scripts/         ручной импорт из Supabase
```

**Роли.** Администраторы работают в `/admin` (сессия 12 часов). Владельцы и сотрудники компаний-клиентов работают только в мини-приложении Telegram: `/start` в боте → пароль компании → заявка операторам → доступ открывает администратор.
