# Good Food — система заказов

Express-сервер отдаёт админ-панель и мини-приложение Telegram. База — Supabase, хостинг — Render.

## Структура

```
server.js        Express: статика, API, вебхук Telegram
src/lib/         Supabase, авторизация, Telegram, FrontPad, заказы, уведомления
src/routes/      auth.js, admin.js, app.js (API мини-приложения), telegram.js
public/admin/    админ-панель
public/app/      мини-приложение Telegram
db/migrations/   миграции для существующей базы
```

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

Админка: http://localhost:3000/admin · мини-приложение: http://localhost:3000/app/

**Render:** Web Service · Build `npm install` · Start `npm start` · Health check `/healthz`.
Переменные окружения — в `.env.example`.

Вебхук бота регистрируется один раз после деплоя:

```bash
curl -F "url=https://ВАШ-СЕРВИС.onrender.com/api/telegram/webhook" \
     -F "secret_token=ВАШ_WEBHOOK_SECRET" \
     "https://api.telegram.org/botВАШ_ТОКЕН/setWebhook"
```

## Роли и вход

- **Админ** — сотрудник компании-владельца сервиса (она одна). Входит в `/admin` по Chat ID и паролю своей компании. Сессия 12 часов.
- **Владелец** и **сотрудник** — люди из компаний-клиентов. Работают только через мини-приложение в Telegram. Личность подтверждает подпись Telegram, в обычном браузере приложение не открывается.

Пароль компании может содержать латиницу, цифры и дефис, до 32 символов.

## Регистрация

1. Человек нажимает `/start` в боте, и появляется запись пользователя без доступа.
2. В приложении он вводит пароль компании. Его привязывают к компании, а в группу операторов приходит заявка.
3. Админ открывает доступ, и после этого можно заказывать.

Сам по себе пароль никого не пускает: без одобрения админа сессии нет.

## Компании

**Пользователи → Компании → Изменить:**

- **Владелец.** В компании он один. Новый владелец заменяет прежнего, тот становится сотрудником.
- **Перевыпустить пароль.** Все сотрудники сразу теряют доступ и возвращаются, когда введут новый пароль. Новый пароль уходит в группу операторов.
- **Доступ** выключает всю компанию целиком.

Разрешить владельцу самому перевыпускать пароль можно в **Настройки → Пароль компании**.

## Заказы

- В приложении две вкладки, «Заказ» и «Возврат». Цены считает сервер, клиент передаёт только позиции и количество.
- Новый заказ приходит в группу операторов. Админ подтверждает или отклоняет его в **Заказы**, заказчику приходит уведомление.
- Заказ можно повторить. Неподтверждённый заказ можно изменить.
- **Настройки → Изменение заказов:** время закрытия приёма, что делать с поздними заказами (на завтра или не принимать), можно ли отменять неподтверждённые.
- **Возврат только из истории:** возвращают строки конкретного заказа, не больше купленного.
- **Снять позицию с продажи** (`available = false`): её нельзя заказать, но можно вернуть.

## FrontPad

Подтверждённый заказ отправляется в FrontPad. Если FrontPad отказал, заказ остаётся «Новым», а причина видна в окне подтверждения.

- Дата доставки: день отправки + 1, время из настроек (`delivery_time`).
- У каждой позиции есть **Артикул FrontPad**. Заказ, где у какой-то позиции нет артикула, не отправляется.
- Возвраты уходят с «Артикулом возврата», только если это включено в настройках.

**Настройки → FrontPad:**

| настройка | по умолчанию | что делает |
|---|---|---|
| `enabled` | выкл | отправлять ли вообще |
| `simulation` | **вкл** | всё собирать и писать в журнал, но не отправлять |
| `verbose` | вкл | подробный лог на Render |
| `send_returns` | выкл | отправлять возвраты |
| `delivery_time` | 10:00 | время доставки |

Статус заказа во FrontPad: `sent` (отправлен), `simulated` (симуляция), `failed` (ошибка), `skipped` (не отправлен, например интеграция выключена). Все попытки, включая пропуски, пишутся в журнал под карточкой настроек. Кнопка «В FrontPad» отправляет заказ повторно.

`FRONTPAD_APIKEY` хранится только на сервере.

## Сообщения

Рассылка до 1000 символов, можно с одним фото. Отправляется всем, выбранным компаниям или выбранным людям. Получают только пользователи с открытым доступом. Отправленное можно удалить из чатов.

## Уведомления (напоминания)

Повторяющиеся сообщения по расписанию: дни недели, время (по Кишинёву), текст, получатели.

- Отправляет их функция в Supabase (Edge Function) по расписанию каждые 5 минут. Функция живёт в Supabase, в этом репозитории её нет.
- Сообщение уходит в течение 5 минут после указанного времени. Если опоздание больше часа, оно не отправляется.
- Каждое уведомление уходит один раз в день.
- Получатель **«Кухне»**: в группу кухни отправляется список на приготовление по подтверждённым заказам на сегодня. Нужен `TELEGRAM_KITCHEN_GROUP_ID`.
- Включить или выключить уведомление можно кликом по статусу.
- «Отправить сейчас» отправляет вручную и не влияет на расписание.

## Бот

- `/start` создаёт пользователя или говорит, что делать дальше: ввести пароль, ждать одобрения или заказывать.
- `/id` показывает Chat ID текущего чата. Так удобно узнать ID группы.

## Смена Chat ID

Chat ID определяет, кто входит. Если с этим ID уже входили, при смене его в админке нужно подтверждение, и сообщение об этом уходит в группу операторов.
