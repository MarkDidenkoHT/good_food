# Good Food — система заказов

Админ-панель и мини-приложение Telegram. Всё работает на вашем компьютере в Docker: сервер, база Postgres, картинки, резервные копии и расписание.

## Установка

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и включите в его настройках запуск при входе в систему. Тогда сервер будет сам подниматься после перезагрузки.
2. Скопируйте `.env.example` в файл **`.env`** (с точкой в начале) рядом с `docker-compose.yml` и заполните его (см. ниже).
3. В папке проекта выполните:

```bash
docker compose up -d
```

4. Откройте http://localhost:3000/admin.

Первый запуск собирает образ, это занимает пару минут. Порт 3000 открыт только на этом компьютере. Из интернета сервер доступен через https-адрес (см. «Адрес сервера»).

Проверить, что всё работает:

```bash
docker compose ps
docker compose logs -f app
```

Оба контейнера должны быть в состоянии `healthy`, а в логе должна быть строка `[server] listening on :3000`.

## Файл `.env`

| переменная | нужна | что это |
|---|---|---|
| `JWT_SECRET` | да | случайная строка, например `openssl rand -hex 32`. Если её сменить, всех разлогинит |
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | да | любая случайная строка |
| `TELEGRAM_ADMIN_GROUP_ID` | да | Chat ID группы операторов (отрицательный). Добавьте бота в группу и отправьте там `/id` |
| `TELEGRAM_KITCHEN_GROUP_ID` | для «Кухни» | Chat ID группы кухни |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | при переносе | откуда загрузить данные при первом запуске |
| `ADMIN_CHAT_ID`, `ADMIN_PASSWORD` | без Supabase | первый админ для пустой базы |
| `FRONTPAD_APIKEY` | для FrontPad | ключ API FrontPad. Если пусто, интеграция выключена |
| `POSTGRES_PASSWORD` | нет | пароль базы, по умолчанию `goodfood`. Задаётся **только до первого запуска** |
| `APP_PORT` | нет | порт на компьютере, по умолчанию `3000` |
| `CLOUDFLARE_TUNNEL_TOKEN` | для туннеля | см. «Cloudflare Tunnel» |

Адреса сервера (URL) в `.env` нет: он задаётся в админке.

После изменения `.env` выполните `docker compose up -d` ещё раз, и контейнер перезапустится с новыми настройками.

## Первый запуск: загрузка данных из Supabase

Новая база пустая. Если есть старая система на Supabase, сервер при первом запуске сам скопирует из неё все данные и картинки.

1. **До первого запуска** впишите в `.env` ключи из Supabase → Project Settings → API:
   - `SUPABASE_URL` — Project URL, например `https://xxxx.supabase.co`;
   - `SUPABASE_SERVICE_ROLE_KEY` — ключ **service_role** (не `anon`).
2. Выполните `docker compose up -d` и смотрите лог:

   ```bash
   docker compose logs -f app
   ```

   Должно появиться:

   ```
   [import] the database is empty — loading from Supabase
   [import] rows: companies …, users …, orders …
   [import] pictures: … copied
   [import] done
   ```

3. Войдите в админку со своим старым Chat ID и паролем компании.

Как это работает:

- Загрузка идёт, **только если база пустая**. При следующих запусках данные не трогаются.
- В Supabase ничего не меняется.
- Если загрузка не удалась (неверный ключ, нет интернета), база остаётся пустой. Исправьте `.env` и снова выполните `docker compose up -d`.
- Строка вида `orders: not imported (no such column here): locked` — это не ошибка. Это старая колонка, которая новой системе не нужна.

**Последняя загрузка в день перехода.** Пока старая система работает, в ней появляются новые заказы. В день перехода откройте в админке **Настройки → Данные из Supabase → «Загрузить данные из Supabase»**. Все данные на сервере заменятся свежими. Текущие данные перед этим сохраняются в резервную копию, а настройка «Адрес сервера» остаётся. Кнопка срабатывает один раз, потом карточка исчезает.

Повторить загрузку из командной строки (заменит всё):

```bash
docker compose run --rm app node scripts/import-supabase.js --replace
```

После перехода ключи Supabase из `.env` можно удалить.

### Без Supabase: первый админ

Если переносить нечего, задайте в `.env`:

- `ADMIN_CHAT_ID` — ваш личный Chat ID в Telegram (отправьте боту `/id` или напишите @userinfobot);
- `ADMIN_PASSWORD` — пароль компании: латиница, цифры и дефис, до 32 символов.

При запуске сервер создаёт этого админа и компанию «Good Food», если их ещё нет. Вход в `/admin`: **Chat ID** = `ADMIN_CHAT_ID`, **пароль** = `ADMIN_PASSWORD`. Существующих пользователей сервер не меняет. Если вы потеряли доступ, удалите этого пользователя в админке и перезапустите сервер: админ создастся заново.

## Адрес сервера (URL)

Telegram работает только с публичным **https**-адресом. Без него бот не получает сообщения, мини-приложение не открывается, а в уведомлениях группы операторов нет кнопок «Открыть в админ-панели».

1. Получите https-адрес, например через Cloudflare Tunnel (см. ниже).
2. В админке откройте **Настройки → Адрес сервера**, введите `https://ваш-домен` и нажмите «Сохранить».
   - Принимается только `https://`, без параметров и `#`. Косая черта в конце убирается сама.
   - При сохранении сервер сразу подключает вебхук бота к этому адресу и показывает, принял ли его Telegram. Для этого в `.env` должен быть `TELEGRAM_BOT_TOKEN`.
   - Если адрес поменялся, просто сохраните новый.
3. В @BotFather → ваш бот → Bot Settings → Menu Button (или Mini App) укажите `https://ваш-домен/app/`.

Адрес хранится в базе, поэтому переживает перезапуски и загрузку из Supabase.

### Cloudflare Tunnel

Туннель даёт https-адрес без проброса портов на роутере.

1. Cloudflare Zero Trust → Networks → Tunnels → Create tunnel (Cloudflared). Скопируйте токен в `.env` → `CLOUDFLARE_TUNNEL_TOKEN`.
2. В туннеле добавьте Public Hostname: ваш домен → Service `http://app:3000`.
3. Запустите вместе с туннелем:

   ```bash
   docker compose --profile tunnel up -d
   ```

4. Сохраните адрес в админке (см. выше).

## Команды

| что сделать | команда |
|---|---|
| запустить | `docker compose up -d` |
| запустить с туннелем | `docker compose --profile tunnel up -d` |
| состояние | `docker compose ps` |
| логи | `docker compose logs -f app` |
| остановить | `docker compose down` |
| обновить после замены файлов | `docker compose up -d --build` |
| скопировать резервные копии в `./backups` | `docker compose cp app:/data/backups ./backups` |

Данные хранятся в томах Docker: `pgdata` (база), `uploads` (картинки), `backups` (копии). `docker compose down` их не удаляет. **`docker compose down -v` удаляет все данные безвозвратно.**

## Резервные копии

- Создаются каждый день в 03:00 по Кишинёву. Если сервер в это время был выключен, копия делается, как только он заработает.
- Хранятся 30 дней. Самая свежая копия не удаляется никогда.
- В админке, в разделе **Настройки → Резервные копии**, есть кнопки «Создать копию» и «Восстановить». Перед восстановлением текущие данные тоже сохраняются.

## Если что-то не работает

| симптом | что проверить |
|---|---|
| в логе `JWT_SECRET is not set` | файла `.env` нет или он называется иначе (например, `env` без точки) |
| не пускает в админку | откройте именно `http://localhost:3000/admin` или https-адрес: по IP локальной сети вход не сохраняется |
| `[db] migration failed` / нет связи с базой | `POSTGRES_PASSWORD` сменили после первого запуска. Верните старый пароль |
| бот молчит | адрес в **Настройки → Адрес сервера** сохранён, Telegram принял вебхук, туннель запущен |
| `[import] startup load failed` | неверные `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` или нет интернета. Исправьте и выполните `docker compose up -d` |

## Разработка без Docker

Нужен Node.js 20+. Postgres ставится вместе с `npm install`, данные лежат в `.local/`.

```bash
npm install
npm run local
```

Остановить: Ctrl+C (если Postgres остался работать — `npm run local:stop`). Загрузка из Supabase: `npm run local:import -- --replace`. Начать с нуля: удалить папку `.local`.

## Структура

```
server.js        запуск: миграции, расписание, загрузка из Supabase, API и статика
src/lib/         база, картинки, Telegram, FrontPad, заказы, уведомления, копии, импорт
src/routes/      auth, admin, app (мини-приложение), telegram (вебхук), files (картинки)
public/admin/    админ-панель
public/app/      мини-приложение
db/migrations/   схема базы, применяется сама (изменения — новым файлом 002_…)
scripts/         запуск без Docker, загрузка из Supabase
```

**Роли.** Админ входит в `/admin` по Chat ID и паролю своей компании (сессия 12 часов). Владельцы и сотрудники компаний-клиентов работают только в мини-приложении Telegram. Регистрация: `/start` в боте → пароль компании в приложении → заявка в группу операторов → админ открывает доступ.
